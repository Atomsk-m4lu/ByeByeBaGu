# 导入解析规格（v1）

> 本文档是 `八股闪背.html` 内置 markdown 导入解析器的正式规格，
> `tests/test-parser.js` 与 `samples/` 里的示例按此规格编写。
> 修改解析器行为时：先改本文档 → 再改代码 → 跑测试 → 在 README「更新历史」记一条。

## 1. 输入与预处理

- 输入：`.md` / `.markdown` / `.txt` 文件，或粘贴的纯文本（UTF-8）。
- 换行统一为 `\n`（兼容 CRLF）。
- **代码围栏保护**：` ``` ` 围栏块（含未闭合到文件尾的）整体替换为占位符，
  策略切分完成后再原样还原进所属卡片的答案；围栏内容不参与任何切分。
- **HTML 注释剔除**：围栏之外的 `<!-- … -->` 在切分前删除（用于笔记里写给自己的批注）。

## 2. 切分策略

| 策略名 | 选择项 | 规则 | 问题 | 答案 |
|---|---|---|---|---|
| `heading` | h2 / h3 / h4 | 指定层级的 ATX 标题开一张新卡，正文（含子层级标题之外的行）为答案；**更高一层**的标题记为卡片标签（tag） | 标题文字 | 标题后到下一张卡前的全部正文 |
| `qa` | — | `问：…` 与 `答：…` 配对；兼容 `Q:`/`A:`、`**问：**`、`【问题】` 等变体，允许一行内 `问：x 答：y` | 问句全文 | 答句全文 |
| `list` | — | 列表项内出现第一个全角冒号 `：` 或半角 `:`，切为问/答；无冒号则整行既是问题也是答案（答案为空，标记诊断） | 冒号前 | 冒号后 |
| `inline` | — | 行内第一个未转义的 ` :: `（语法来自 obsidian-spaced-repetition） | `::` 前 | `::` 后 |

## 3. 自动识别

`auto` 依次对四种策略试切并打分，取最高分：

- 有效卡数（问/答均非空）为主分；
- 答案过短（< 8 字符）与超长（> 1500 字符，超过 `LONG_ANSWER` 阈值）扣分；
- 标题策略要求题目行确实是标题、且层级一致；
- `qa` / `list` / `inline` 要求匹配率（命中行 / 总行）达到阈值，避免误切普通散文。

## 4. 诊断项

预览区对每张卡标记：

- `空答案` — 切出的答案为空；
- `超长答案` — 超过 1500 字符（建议拆卡）；
- `重复` — 与已入库卡片（或同批内）内容哈希相同，勾选「跳过重复」时直接丢弃。

去重键：`hash(q + '|' + a)`（djb2），与卡片 id 无关，同内容换标题/卡组名也会命中。

## 5. 卡片落库

新卡初始字段：`s=0, d=0, state='new', due=导入时间, last=null, interval=0, lapses=0, leech=false, history=[]`。
同一批多文件导入时共用一个去重集合；`db.lastImport` 记录本次卡组 id 以支持一键撤销。

## 6. 不做的事（有意为之）

- 不解析 YAML front matter（`---` 开头的块按水平线处理，不提取元数据）；
- 不递归把子标题也切成卡（标题策略只按选定层级一层切）；
- 不处理表格/脚注语法（原样进答案，由渲染层的 mdLite 展示）。
